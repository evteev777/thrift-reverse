# thrift-reverse

Обратный генератор `.thrift` из **исходников Java, сгенерированных Apache Thrift**.
Рекурсивно читает каталог, восстанавливает контракт без компиляции и выполнения Java.
Maven, JDK, Lombok и зависимости старого проекта ему не нужны.

Python 3.10+; сторонних Python-зависимостей нет. Docker использует Python 3.12.
Это CLI для разового запуска, а не постоянно работающий сервер.

## Быстрый запуск: Docker Compose

Клонируй репозиторий и перейди в каталог проекта:

```bash
git clone https://github.com/evteev777/thrift-reverse.git
cd thrift-reverse
mkdir -p output
cp .env.example .env
vim .env
```

В `.env` укажи путь к корню исходников (можно к `src/main/java` всего проекта):

```dotenv
INPUT_DIR=/home/user/project/src/main/java
OUTPUT_DIR=./output
LOCAL_UID=1000
LOCAL_GID=1000
```

Свои UID/GID посмотри командами `id -u` и `id -g`. Каталоги input/output должны существовать;
output должен быть доступен этому пользователю для записи. Пути с пробелами в `.env` заключай в кавычки.
Пустые каталоги `input/` и `output/` уже входят в репозиторий: вместо изменения INPUT_DIR можно скопировать Java туда.

Обычное восстановление:

```bash
docker compose run --rm --build reverse
```

**Восстановление под 0.24.0 с обязательной проверкой этим compiler:**

```bash
docker compose run --rm --build reverse-024
```

Явный запуск сервиса автоматически активирует его Compose profile. Нужны Docker с BuildKit
и Docker Compose v2. Сеть нужна при первой сборке образа; во время обработки исходников
сеть контейнеру отключена. Исходники монтируются только для чтения и в образ не включаются.

Можно запускать и через `up`:

```bash
docker compose up --build --abort-on-container-exit --exit-code-from reverse reverse
```

После завершения контейнер остановится. Для режима проверки аналогично укажи сервис `reverse-024`.

Повторный запуск в тот же output требует явного `--force`:

```bash
docker compose run --rm reverse-024 \
  /input --output /output --target 0.24.0 --validate --force
```

**Аргументы после имени сервиса заменяют весь `command`.** Поэтому указывай пути, профиль
и `--validate` полностью, как в примере. ENTRYPOINT остаётся генератором.

## Результат

По одному файлу на Java package:

```text
output/
  pkg_ru_example_api.thrift
  pkg_ru_example_model.thrift
  report.json
```

Сохраняется `namespace java`; ссылки между пакетами становятся `include` и квалифицированными
именами типов. Имена выходных файлов вычисляются из **полного** package, а не только последнего сегмента.
В `report.json`: версии исходного compiler, количество файлов/типов/методов/полей,
пропущенные обычные Java-файлы, предупреждения, ограничения и результат проверки compiler.
Счётчик `fields` учитывает поля структур, исключений и union; поля аргументов/результатов сервисов в него не входят.

Если два разных package дают одинаковое имя файла после замены точек на `_`, генератор
остановится. Цикл package-зависимостей также приводит к ошибке: циклические include не создаются.

## Что восстанавливается

- `struct`, `exception`, `union`, `enum` с числовыми значениями.
- Имена и номера полей; `required`, `optional`, отсутствие модификатора (`DEFAULT`).
- `bool`, `byte`/`i8`, `i16`, `i32`, `i64`, `double`, `string`, `binary`, `uuid`.
- `list`, `set`, `map`, в том числе вложенные; ссылки на пользовательские типы.
- Сервисы, аргументы с исходными ID, результат, объявленные исключения, `oneway`, наследование сервисов.
- Простые значения по умолчанию из конструктора без аргументов: числа, bool, строки, enum.
- Разрешение полных Java-имён, имён в своём package, явных импортов и wildcard-импортов.

Реализация — специализированный токенизатор и анализатор шаблонов Apache Thrift Java generator.
Комментарии, строковые литералы и границы вложенных классов учитываются; исходники не выполняются.
Это не универсальный парсер произвольного Java-кода и не средство восстановления Thrift из обычных POJO.

Для структуры нужны `TField` и `FieldMetaData`/`metaDataMap`.
Для сервиса нужны вложенные `Iface`, `*_args`, `*_result` и `Processor` с `isOneway()`.
Отсутствие `*_result` само по себе не трактуется как `oneway`.
Метаданные проверяются на дубли ID/имён, полноту и согласованность с типом в `TField`.
Неизвестные формы завершают работу ошибкой вместо генерации заглушек.

## Профиль 0.24.0

У IDL нет отдельного заголовка «версия 0.24.0». Базовые конструкции старого контракта
обычно остаются теми же; изменение Java API не означает, что надо изменить контракт.

| Режим | Поведение |
| --- | --- |
| `--target portable` (по умолчанию) | Стандартный IDL; 8-битное целое обозначается `byte`. Версия compiler не фиксируется. Не гарантирует поддержку новых типов, например `uuid`, старыми compiler. |
| `--target 0.24.0` | Для 8-битного целого используется `i8`; при `--validate` требуется именно compiler 0.24.0. |
| `--validate` | Compiler читает каждый выходной IDL и генерирует Java во временный каталог. Ошибка блокирует запись результата. Исходная и полученная Java **не компилируются**. |

В сервисе Compose `reverse-024` включены **оба** флага: `--target 0.24.0 --validate`.
Один `--target 0.24.0` без `--validate` не означает, что результат проверен compiler.

Образ проверки собирает compiler из официального `thrift-0.24.0.tar.gz` с проверкой
зафиксированного SHA-256. Используются C++-исходники и готовые lexer/parser из релизного архива;
собирается только Java backend, необходимый для проверки. Это не полный SDK Thrift и не
универсальный образ compiler для всех языков. Исходный код compiler не модифицируется.
Лёгкий образ `reverse` этот этап не собирает при использовании BuildKit.

Документация IDL: https://thrift.apache.org/docs/idl
Релизы: https://github.com/apache/thrift/releases

## Опции

```bash
python3 thrift_reverse.py /path/to/java --output ./output
python3 thrift_reverse.py --help
```

| Опция | Назначение |
| --- | --- |
| `--target portable\|0.24.0` | Профиль выходного IDL. |
| `--validate` | Проверить результат установленным Thrift compiler. |
| `--thrift /path/to/thrift` | Путь к compiler, по умолчанию `thrift` из PATH. |
| `--defaults strict` | По умолчанию: сохранять простые defaults; сложные/неподдержанные отклонять. |
| `--defaults omit` | Явно удалить **все обнаруженные defaults**, записать предупреждения. Меняет семантику контракта; требует ручной проверки. |
| `--namespace ru.example.recovered` | Объединить в `recovered.thrift`, заменив Java namespace. Нужны уникальные имена типов; меняются пакеты при последующей генерации Java. |
| `--exclude '*/target/*'` | Повторяемый glob относительно input, семантика `pathlib.Path.match`. |
| `--force` | Разрешить замену совпадающих имён результата. Посторонние и устаревшие файлы не удаляет. |

Пример исключения дублирующего дерева:

```bash
docker compose run --rm reverse /input -o /output --exclude '*/generated-sources/*'
```

Лучше сразу указывать узкий корень с нужными исходниками. Если копии одного Java-типа найдены
несколько раз, выполнение останавливается; нельзя случайно смешать разные версии контракта.
Символические ссылки на Java-файлы и подкаталоги не обходятся.
Входные файлы должны быть UTF-8 (BOM допускается).

Коды возврата: `0` — успех, `2` — ошибка восстановления, проверки или файловой операции.
JSON-краткая сводка выводится в stdout; ошибки и предупреждения — в stderr.
Все разборы и проверка compiler заканчиваются до изменения output.
Запись каждого файла атомарна, но вся директория не является единой транзакцией:
при дисковой ошибке во время записи возможно частичное обновление нескольких файлов.
Для нового прогона предпочтительнее новый каталог результата.

## Что нельзя гарантировать

1. Исходные имена `.thrift`, исходное разбиение по файлам и include, комментарии,
   namespaces других языков и исходные аннотации не восстанавливаются.
2. `typedef` обычно стирается при генерации Java. Генератор не угадывает его имя;
   обнаруженная строковая typedef-метаинформация пока приводит к ошибке.
3. Отдельные классы констант (`*Constants`) пока не поддержаны. Если файл помечен как
   сгенерированный Apache Thrift, но не распознан, будет ошибка. Не исключай его молча,
   если константы нужны в восстановленном контракте.
4. Сложные defaults (коллекции, структуры, binary, UUID, вычисления, вызовы методов)
   не вычисляются. По умолчанию — ошибка; `--defaults omit` даёт явное восстановление с потерями.
   Необычные Java escape-последовательности в строках также могут потребовать ручной доработки.
5. Если Java-классы вручную меняли, defaults и метаданные могут уже отличаться от исходного IDL.
   Тела `read()`/`write()` и пользовательский бизнес-код не анализируются.
6. Проверка compiler подтверждает синтаксис и корректность ссылок, а не полную сетевую
   совместимость с работающей системой. Перед заменой старых классов нужен интеграционный тест клиента/сервера.
7. Автоматические интеграционные тесты используют исходники, сгенерированные compiler 0.24.0.
   Поддержка всех исторических версий, генераторных флагов, Facebook Swift/fbthrift не заявляется.

## Тесты

Без Docker, только тесты токенизации/метаданных:

```bash
python3 -m unittest discover -s tests -v
```

Полный набор с compiler 0.24.0:

```bash
THRIFT_BIN=/path/to/thrift python3 -m unittest discover -s tests -v
```

В Docker:

```bash
docker compose run --rm --build tests
```

Интеграционные тесты сначала создают Java из тестового IDL, восстанавливают IDL, снова
генерируют Java и проверяют стабильность повторного восстановления. Java не компилируется.
Тестируются union, exception, oneway/void, наследование, binary, UUID, вложенные контейнеры,
межпакетные ссылки, defaults и ошибки неполных/дублирующих исходников.

Фактические проверки при подготовке выпуска описаны в `VALIDATION.md`.
